The parametric law is not identified on these suites. Fitted to the same DataDecide checkpoints, Chinchilla's Approach 3 returns 1.6 tokens/param with the irreducible loss E pinned at its bound. Switching the learning-rate-schedule correction off moves it to 209. All headline numbers above use IsoFLOP profiles (Approach 2), which make no functional-form assumption.

Why checkpoint suites are hard

  1. A checkpoint is not a shorter run. Mid-schedule the learning rate is still high, so loss sits above what a run annealed at that length reaches. Chinchilla trained separate runs; public suites release one run per size.
  2. In Pythia the schedule confound cannot be estimated. Every run ends at 300B tokens, so run fraction f = D / 300B is a function of D alone, and any schedule effect is absorbed into B·D−β. DataDecide ends each run at 100 tokens/param (f = D / 100N), which is identifiable, but weakly.
  3. Checkpoints are not independent. Consecutive checkpoints share initialisation, data order and optimiser state. Bootstrapping them i.i.d. treats ~800 correlated points as independent evidence.

Method

L(N, D, f) = E + A·N−α + B·D−β + K·[η(f) − η(1)] / 10⁻³   ·   r(C) = G−2(C/6)(α−β)/(α+β)
  • Fit: log-sum-exp parameterisation, Huber δ = 10⁻³ on log-residuals, L-BFGS-B from the best points of Hoffmann's 4,500-point grid, analytic gradients checked against finite differences.
  • Schedule term (DataDecide): η is the absolute learning rate (cosine to 1% of peak, peak ∝ N−1/3). Fit on checkpoints up to 70% of each run, predict every final loss: log-MAE 0.033 → 0.015.
  • IsoFLOP from checkpoints: interpolate each run at fixed C = 6ND, parabola in log N around the minimum, keep interior minima, fit Nopt ∝ Ca.
  • Bootstrap units: checkpoints, evaluation sequences (paired across sizes), seeds within size, model sizes, and combinations. B = 1,000 for headlines, 200 per one-at-a-time specification.
  • Multiverse: loss function, parameter counting, size subset, fit start, tail handling, checkpoint weighting, α = β, schedule term, evaluation set; 2,880 + 1,536 factorial specifications.

Data checks

Pythia's small deduped models get worse late in training, which decides which checkpoints a fit may use. We re-measured that on our own Pile-validation sample on a T1000 GPU.

The degradation is real for 70M and 160M, but the released data overstate it about 4–5×. The late rise the released data show for 410M and 1.4B does not reproduce: we measure a small decrease for both. Every baseline fit therefore stops each run at its smoothed loss minimum.

Limits

  • Pythia has seven sizes (no 1B split was released), so the size bootstrap is itself approximate; 69% of resamples yield an interior IsoFLOP minimum.
  • The schedule term assumes excess loss proportional to the current learning rate, with no lag and one global K. It is validated out of sample, not derived.
  • Pythia's IsoFLOP estimate still carries schedule bias that no fit on this suite can remove.
  • C = 6ND ignores attention FLOPs. DataDecide's smallest models are embedding-dominated, which is why parameter counting matters there.
